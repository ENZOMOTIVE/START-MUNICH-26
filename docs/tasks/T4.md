# T4 — CRM and frontend sessions (#24)

Operator view of each RFQ: stage, deadline, timeline, quote, booking. No mailbox or pricing logic here.

## Owned folders

- `frontend/` (create app)
- Session/CRM read APIs (new modules; do not overwrite T1 contracts/db)
- `frontend/Dockerfile`

## Inputs

- `Session`, `SessionEvent` contracts
- Workflow updates from T3 (`stage`, events)
- Demo scenario last steps: `crm_timeline`, `dashboard`

## Outputs

- Dashboard on `127.0.0.1:5173`
- Session list + thread timeline
- Generated client from `make openapi` (`frontend/openapi.json`)

## Run with fixtures

```sh
make setup
make dev
make demo
# open http://127.0.0.1:5173
```

Expect one simulated session for `demo-thread`: intake → pricing → quoted (Yellowtail `412.50` EUR) → accepted → booked.

## What the scaffold already implements

- `Session` / `SessionEvent` / `SessionStage`
- `sessions` unique on `rfq_id`; `session_events` ordered by `occurred_at`
- Repositories: `list_sessions`, `events_for`, `append_event`
- Frontend compose service on `127.0.0.1:5173` (wget healthcheck optional)

## Remaining work + acceptance

- Vite/React (or equivalent) on Node 22 + pnpm
- `pnpm typecheck` and `pnpm build` for CI
- `pnpm openapi` after `make openapi`
- Read APIs for sessions/events (demo data only until T3 writes rows)
- Never put `HACKATHON_API_KEY` or `GATEWAY_OPENAI_KEY` in the bundle

Acceptance: after `make demo`, the dashboard shows the happy-path timeline without calling live mailbox/portal.
