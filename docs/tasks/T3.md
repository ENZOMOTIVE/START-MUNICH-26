# T3 — Workflows: RFQ, selection, booking (#23)

Turn a routed RFQ plus candidates into a quote, then an acceptance into a simulated booking.

## Owned folders

- `backend/app/workflows` (create)

## Inputs

- `RFQ` from T1 router
- `RateCandidate[]` from T2
- `fixtures/messages/demo-acceptance.json`
- `fixtures/scenarios/demo-happy-path.json`

## Outputs

- `QuoteDecision` (one per RFQ)
- `ActionIntent` `kind=first_quote` (unique per RFQ)
- `Booking` with `team_reference`; demo status `confirmed`, `simulated: true`

## Run with fixtures

Happy path is fully simulated:

1. inbound RFQ (`demo-rfq.json`)
2. persist
3. route (`classification=rfq`)
4. fixture prices (`demo-fra-lax.json`)
5. select cheapest Yellowtail `412.50` EUR / `R-DEMOYELLOW01`
6. quote action (no live mail)
7. acceptance (`demo-acceptance.json`, subject `RE: RFQ`)
8. booking confirmed
9. CRM timeline + dashboard (T4 consumes this)

```sh
make demo
```

## Implementation breakdown

1. Validate the routed RFQ fields and preserve the original message timestamp as the start of its six-minute lifetime.
2. Load T2 candidates, ignore incomplete or expired offers, and select cheapest or fastest. Fastest selection requires transit time.
3. Persist the selected offer and the selection rule, considered candidates, exclusions, source, validity, and charges as quote evidence.
4. Create one stable `first_quote` intent per RFQ. Delivery stays simulated in demo mode.
5. Match acceptance to the RFQ thread, require a stored quote, and create one simulated confirmed booking with a stable `team_reference` and booking intent.
6. Publish quote, acceptance, booking, and exception details to the session timeline for T4.

## Acceptance

- The demo fixture selects Yellowtail `412.50` EUR / `R-DEMOYELLOW01` as cheapest and Helix as fastest.
- Incomplete and expired offers cannot be selected; fastest requests cannot select an offer without transit time.
- Duplicate RFQ or acceptance delivery does not create another quote or booking intent.
- A quote dispatch after the RFQ or selected rate expires is blocked and recorded as an exception.
- Acceptance without a stored quote cannot advance the session or create a booking.
- The happy path ends with one simulated confirmed booking on the demo thread, without live mail or portal calls.

## Scope boundary

- No live carrier negotiation, adaptive-wait, or live portal booking in this task.
- Live carrier and portal adapters remain follow-up work; demo booking stays simulated.
