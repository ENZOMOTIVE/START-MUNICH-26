# T3 — Workflows: RFQ, selection, booking (#23)

Turn a routed RFQ plus candidates into a quote, then an acceptance into a simulated booking.

## Owned folders

- `backend/app/workflows` (create)

## Inputs

- `RFQ` from T1 router
- `RateCandidate[]` from T2
- `fixtures/messages/demo-acceptance.json`
- `fixtures/scenarios/demo-happy-path.json`

## Outputs

- `QuoteDecision` (one per RFQ)
- `ActionIntent` `kind=first_quote` (unique per RFQ)
- `Booking` with `team_reference`; demo status `confirmed`, `simulated: true`

## Run with fixtures

Happy path is fully simulated:

1. inbound RFQ (`demo-rfq.json`)
2. persist
3. route (`classification=rfq`)
4. fixture prices (`demo-fra-lax.json`)
5. select cheapest Yellowtail `412.50` EUR / `R-DEMOYELLOW01`
6. quote action (no live mail)
7. acceptance (`demo-acceptance.json`, subject `RE: RFQ`)
8. booking confirmed
9. CRM timeline + dashboard (T4 consumes this)

```sh
make demo
```

## What the scaffold already implements

- `WorkflowStatus`, `QuoteDecision`, `ActionIntent`, `Booking` models
- Unique first-quote index and unique `team_reference`
- Repositories: `first_quote_intent`, `quote_for`, `booking_for`
- Scenario fixture listing every step as `simulated: true`

## Remaining work + acceptance

- Selection: `service_intent=cheapest` → min total among `complete=true`; `fastest` → min `transit_days` with complete candidates
- Persist `quote_decisions.evidence` (why this candidate)
- Create `action_intents` with stable `action_key`; demo delivery stays simulated
- On acceptance classification, create booking without calling POST `/v1/portal/bookings` unless `live_allowed()`
- No live carrier negotiation; no adaptive-wait

Acceptance: demo scenario ends with Yellowtail selected, a quote intent, and a confirmed simulated booking on `demo-thread`.
